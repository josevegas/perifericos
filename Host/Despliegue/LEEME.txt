================================================================================
 SmartOne.Perifericos.Host
 Servicio local de periféricos para la caja
================================================================================

QUÉ ES ESTO
  Un servicio que corre en la misma PC de la caja y escucha SÓLO en
  127.0.0.1:5005. La API de FastAPI le pide por HTTP los cobros con pinpad y la
  impresión de comprobantes. No abre nada hacia la red: no es un servicio
  expuesto, no necesita reglas de firewall ni permisos de administrador.

AGENTE BRIDGE PARA API REMOTA
  Si FastAPI está en un servidor remoto, la caja puede mantener un canal
  WebSocket saliente cifrado (WSS). Así el servidor envía cobros, anulaciones y
  pruebas de Pinpad sin abrir puertos entrantes ni publicar el HTTP local.
  PostgreSQL del backend conserva la cola compartida entre sus workers.

  El Bridge usa una credencial independiente por terminal. El token del Bridge
  NO es el token.txt de HTTP local: no se reutiliza entre cajas.

REQUISITOS DE LA CAJA
  - Windows de 64 bits (el ejecutable es x64).
  - .NET Framework 4.8. Viene de fábrica en Windows 10 1903 o superior.
    Si falta: https://dotnet.microsoft.com/download/dotnet-framework/net48
  - Pinpad Ingenico/Niubiz conectado por USB y encendido.
  - Impresora térmica ESC/POS instalada en Windows. Si la ticketera está
    conectada pero todavía no tiene su cola, ver "IMPRESORA DE TICKETS".
  - El token del servicio, que es un secreto compartido con la API de FastAPI.
    No hace falta conseguirlo a mano: el paquete ya trae uno pregrabado en
    token.txt y, si la API vive en esta misma PC, el instalador adopta su
    PERIFERICOS_TOKEN (ver "EL TOKEN DEL SERVICIO").

INSTALACIÓN EN 3 PASOS
  1. Copie ESTA CARPETA COMPLETA a la PC de la caja, por ejemplo a
     C:\Perifericos. El .exe y las DLL no se separan nunca: las DLL nativas de
     Ingenico tienen que quedar junto al ejecutable.

  2. Si el paquete llegó dentro de un ZIP descargado de otra máquina o de
     internet, Windows le pone "marca de bloqueo" a los scripts. Quítela antes
     de instalar. En PowerShell, dentro de la carpeta:

        Get-ChildItem | Unblock-File

  3. Ejecute el instalador:

        powershell -NoProfile -ExecutionPolicy Bypass -File .\Instalar.ps1

     Si la API de FastAPI vive en esta misma PC, el instalador encuentra su
     .env, adopta su PERIFERICOS_TOKEN y deja los dos lados iguales. Si la API
     todavía no tiene token, genera uno y lo escribe en los dos archivos; lo
     único que queda por hacer a mano es reiniciar la API.

     Si no aparece ningún .env, el host igual arranca: reusa el token.txt que
     viene pregrabado en el paquete y el informe lo imprime para que lo copie
     en PERIFERICOS_TOKEN de la API.

     Puede fijar la impresora a mano, si hay más de una:

        powershell -NoProfile -ExecutionPolicy Bypass -File .\Instalar.ps1 -Impresora "EPSON TM-T20III"

     El nombre tiene que ser el exacto de una cola ya instalada; se ve con
     Get-Printer. Si se equivoca, el instalador ahora dice cuál es la térmica
     que sí está instalada en vez de mandarlo a crear una cola duplicada.

     Y si la caja todavía no tiene la cola de la ticketera, el instalador la
     puede crear en la misma pasada (pide permisos de administrador):

        powershell -NoProfile -ExecutionPolicy Bypass -File .\Instalar.ps1 -PrepararImpresora

     Sólo si la API está en OTRA máquina hay que llevar el token a mano:

        powershell -NoProfile -ExecutionPolicy Bypass -File .\Instalar.ps1 -SinTocarApi

  El instalador comprueba la máquina, escribe token.txt, registra el arranque
  automático, levanta el servicio y hace la prueba de humo. Al final imprime un
  informe con OK / AVISO / FALLO. Se puede volver a ejecutar las veces que haga
  falta: es idempotente.

  Para activar el Bridge remoto, configure en el backend la migración, el
  transporte `PERIFERICOS_PINPAD_TRANSPORTE=bridge` y una credencial única para
  cada código de terminal en `PERIFERICOS_BRIDGE_TOKENS`. En la caja, cree estos
  archivos junto a IniciarPerifericos.cmd antes de iniciar:

    bridge-url.txt       wss://api.ejemplo.com/api/v1/perifericos/pinpad/bridge
    bridge-terminal.txt El código de la caja, igual al del turno de POS
    bridge-token.txt    El secreto único de esta caja, igual al del backend

  bridge-url.txt acepta dos transportes y se elige por el esquema de la URL:

    ws://, wss://     Canal WebSocket: un solo socket abierto. Es el preferido,
                      pero exige que el proxy reenvíe el upgrade (en nginx,
                      proxy_set_header Upgrade y Connection "upgrade"). El
                      backend no tiene bandera de excepción para este canal:
                      ws:// remoto se cierra con el código 4403, así que un
                      servidor publicado solo en http:// necesita el
                      transporte de larga encuesta.
    http://, https:// HTTP de larga encuesta: la caja deja una petición abierta
                      contra …/perifericos/pinpad/agente y el servidor responde
                      en cuanto hay una orden o al vencer el plazo. Atraviesa
                      proxies que solo reenvían HTTP normal, sin tocar el
                      upgrade. La ruta de la sesión se deriva de la misma URL,
                      así que …/pinpad/bridge pasa a ser …/pinpad/agente.

  Por omisión el agente exige wss:// o https:// fuera de loopback y valida el
  certificado del servidor. Si el backend todavía no tiene TLS (por ejemplo,
  publicado en http:// con IP y puerto directos), cree además:

    bridge-insecure.txt  1

  Esa bandera habilita ws:// y http:// sin cifrar hacia un equipo remoto y
  desactiva la validación del certificado (necesario mientras el certificado
  sea autofirmado o esté vencido). Con ella el token de la caja viaja en texto
  plano por la red y la conexión queda expuesta a intercepción: úsela solo en
  pruebas o en una red controlada, y retírela en cuanto el backend tenga un
  certificado válido con SAN para el nombre o IP que figura en bridge-url.txt.
  Al arrancar, el host imprime un AVISO en consola cuando este modo está activo.

  Con http:// remoto el backend responde 403 a propósito, porque el token
  viajaría sin cifrar. Para aceptarlo, además, el servidor debe definir
  PERIFERICOS_BRIDGE_HTTP_INSEGURO=true en su .env.

  bridge-token.txt es secreto local en texto plano para el proceso del agente:
  limite su lectura al usuario de Windows que ejecuta la tarea y a los
  administradores. No lo incluya en ZIP, repositorios, tickets ni logs. El
  archivo está excluido de Git. Reinicie el host al cambiar la configuración.
  El proxy de la API debe reenviar X-Forwarded-Proto y estar configurado como
  proxy confiable para que el backend pueda verificar que la conexión usa TLS.
  Solo se necesita salida HTTPS/WSS hacia el servidor; no se abre el puerto
  5005 a la red.

  Antes de culpar al agente, confirme que el puerto del backend sea alcanzable
  desde la caja:  Test-NetConnection <ip> -Port <puerto>  debe dar True. Si el
  firewall del servidor descarta el puerto, el host reintenta con espera
  creciente y la consola muestra "Bridge desconectado ... no ha podido
  responder": eso es red, no configuración.

  En Bridge, los cobros, anulaciones y pruebas deben llevar el mismo
  codigo_terminal configurado en la caja y un turno abierto a nombre del usuario
  autenticado. Si la conexión se pierde después de enviar un cobro, el servidor
  no vuelve a enviarlo automáticamente: revise el voucher antes de reintentar.

QUÉ HACE EL INSTALADOR
  1. Comprueba Windows x64 y .NET Framework 4.8.                    (bloqueante)
  2. Comprueba que estén los 10 archivos del paquete.               (bloqueante)
  3. Revisa la impresora térmica y el pinpad.                     (sólo aviso)
     Con -PrepararImpresora, además crea la cola que falte.
  4. Si pasa -Impresora, la fija en impresora_ticket del .exe.config.
  5. Resuelve el token con la API (ver "EL TOKEN DEL SERVICIO"), escribe
     token.txt y registra la tarea programada de arranque automático.
  6. Levanta el host y consulta /api/v1/impresion/estado y
     /api/v1/pinpad/probar.

  El pinpad y la impresora que falten son AVISO, no FALLO: la caja puede
  instalarse sin ellos y conectarlos después. Lo que sí bloquea es una máquina
  de 32 bits, la falta de .NET 4.8 o un archivo faltante.

  Si algo sale FALLO, el instalador no registra ni arranca nada y termina con
  código 1. Corrija y vuelva a ejecutarlo.

IMPRESORA DE TICKETS
  El módulo imprime por el spooler de Windows, con datos ESC/POS crudos, y sólo
  en la cola de la ticketera: NUNCA usa la impresora predeterminada. Por eso una
  cola mal elegida no imprime en cualquier lado, se niega a imprimir.

  Una ticketera recién conectada por USB aparece en el Administrador de
  dispositivos, pero no siempre aparece en "Impresoras y escáneres". Hasta que no
  exista la cola, el host responde disponible:false y no imprime. Este script
  crea esa cola con el driver de bandeja "Generic / Text Only" (el que deja
  pasar los bytes ESC/POS sin reinterpretarlos) sobre el primer puerto USB libre:

        powershell -NoProfile -ExecutionPolicy Bypass -File .\PrepararImpresora.ps1

  Pide permisos de administrador: se vuelve a abrir solo y hay que aceptar el
  aviso de Windows. Es idempotente: si la cola ya existe con ese driver no toca
  nada. Otras formas de usarlo:

        .\PrepararImpresora.ps1 -Nombre "EPSON TM-T20III"   otro nombre de cola
        .\PrepararImpresora.ps1 -Puerto "LPT1"              otro puerto
        .\PrepararImpresora.ps1 -Forzar                     la rehace
        .\PrepararImpresora.ps1 -Quitar                     la elimina

  El nombre de la cola importa: si no se fija con -Impresora, el módulo busca una
  cola que contenga TM-T, TM-U, EPSON TM, RECEIPT, TICKET, THERMAL o POS-, en ese
  orden. "EPSON TM-T20III" lo cumple.

  Después de crearla no hace falta reiniciar el host: el módulo resuelve la
  impresora en cada comprobante.

  Si prefiere hacerlo a mano: Configuración > Impresoras y escáneres > Agregar
  una impresora > "Agregar una impresora local manualmente" > puerto USB001 >
  controlador "Generic / Text Only" > nombre "EPSON TM-T20III".

EL TOKEN DEL SERVICIO
  El token es un secreto compartido: la API lo manda en el encabezado
  X-Peripheral-Token y el host lo exige en cada petición. Los dos valores tienen
  que ser iguales, y el host no arranca con uno de menos de 32 caracteres.

  Como la API de FastAPI corre en esta misma PC, el instalador evita copiarlo a
  mano. En este orden, toma el token:

    1. De -Token, si se lo pasó.
    2. De -TokenAuto, que genera uno nuevo y rota con él el de la API.
    3. Del .env de la API, si declara PERIFERICOS_TOKEN con valor.
    4. Del token.txt que ya exista en esta carpeta: el que trae el paquete.
    5. Y si no, genera uno y lo escribe en los dos lados.

  El token.txt del paquete es un valor al azar que se genera al armarlo, distinto
  en cada paquete. Se reemplaza solo cuando la API tiene uno propio: la API manda.

  Antes de tocar el .env guarda un respaldo: el anterior queda como .env.bak en
  la carpeta de la API.

  El .env se busca solo entre las carpetas vecinas a ésta. Si la API está en
  otro sitio:

        .\Instalar.ps1 -EnvApi "C:\ruta\al\.env"

  Si la API vive en OTRA máquina su .env no se alcanza desde aquí:

        .\Instalar.ps1 -SinTocarApi

  En ese caso el instalador genera el token, lo imprime en pantalla y deja
  token.txt con él; hay que copiarlo a PERIFERICOS_TOKEN en la API y reiniciarla.

  Con el token pregrabado del paquete no hay que hacer nada más que copiarlo a
  la API: el informe lo muestra tal cual, por si esa caja no tiene .env.

TARJETA DE REFERENCIA
  Instalar o reparar         .\Instalar.ps1 [-Impresora "..."]
  Instalar con token nuevo   .\Instalar.ps1 -TokenAuto
  API en otra ruta           .\Instalar.ps1 -EnvApi "C:\ruta\al\.env"
  API en otra máquina        .\Instalar.ps1 -SinTocarApi
  Comprobar sin arrancar     .\Instalar.ps1 -SinArrancar
  Detener y desinstalar      .\Instalar.ps1 -Quitar
  Crear la cola de tickets   .\PrepararImpresora.ps1
  Cola y todo de una vez     .\Instalar.ps1 -PrepararImpresora
  Arrancar viendo la consola .\IniciarPerifericos.cmd
  Estado del arranque        Get-ScheduledTaskInfo -TaskName 'SmartOne.Perifericos.Host'
  Armar el paquete           .\CrearPaquete.ps1 -DetenerServicio
  Paquete con token fijo     .\CrearPaquete.ps1 -Token "<32 caracteres o más>"
  Paquete sin token.txt      .\CrearPaquete.ps1 -SinToken

  LastTaskResult 267009 (0x41301) significa "en ejecución". El valor
  2147946720 (0x800710E0) que aparece cuando el host ya está corriendo es la
  negativa normal del reintento de cada minuto, no un error.

VERIFICACIÓN
  Con el servicio levantado, en esta misma carpeta:

    $t = (Get-Content .\token.txt -Raw).Trim()
    $h = @{ 'X-Peripheral-Token' = $t }
    Invoke-RestMethod -Method Post -Uri http://127.0.0.1:5005/api/v1/impresion/estado -Headers $h -Body '{}' -ContentType 'application/json'
    Invoke-RestMethod -Method Post -Uri http://127.0.0.1:5005/api/v1/pinpad/probar      -Headers $h -Body '{}' -ContentType 'application/json'

  Le tiene que responder HTTP 200. Un 401 significa que el token no coincide
  con PERIFERICOS_TOKEN de la API.

BITÁCORAS
  host.log    Arranques, salidas y errores del host.
  pinpad.log  Apertura de PCL, trama enviada y trama recibida de cada cobro.
              Es la fuente principal cuando un cobro falla.

  Ambas se escriben en esta carpeta. Cuando pida soporte, mande las dos.

SI ALGO FALLA
  El instalador no arranca, no pasa nada
    Ábralo desde una consola de PowerShell en vez de doble clic, así ve el
    mensaje de error. Verifique la política de ejecución con
    Get-ExecutionPolicy.

    Si el ZIP vino de internet: Get-ChildItem | Unblock-File

  "Configure PERIFERICOS_TOKEN con al menos 32 caracteres antes de iniciar."
    El host no arranca sin token. Ejecute .\Instalar.ps1 —toma el de la API o
    genera uno y lo deja en los dos lados— o escriba token.txt a mano (una sola
    línea, 32 caracteres o más).

  "Ya hay un servicio de periféricos en marcha en esta sesión de Windows"
    Se lanzó el host cuando ya estaba corriendo: el reintento automático de cada
    minuto, o un doble clic. No es un error. Sólo hay que detenerlo y volver a
    arrancarlo si cambió token.txt o SmartOne.Perifericos.Host.exe.config, para
    que lea los valores nuevos.

  HTTP 401 en las pruebas
    token.txt no coincide con PERIFERICOS_TOKEN de FastAPI. Vuelva a ejecutar
    el instalador: adopta el de la API y sincroniza los dos lados. Recuerde que
    la API lee su .env sólo al arrancar, así que después de un cambio de token
    hay que reiniciarla.

  La impresora no está disponible
    El módulo NUNCA usa la impresora predeterminada de Windows. O el nombre de
    la cola coincide con TM-T, TM-U, EPSON TM, RECEIPT, TICKET, THERMAL o POS-,
    o hay que fijarla: .\Instalar.ps1 -Impresora "nombre exacto de la cola".

    Si la ticketera está conectada y aun así sale disponible:false, lo más
    probable es que falte la cola en Windows: ejecute .\PrepararImpresora.ps1 o
    revise la sección "IMPRESORA DE TICKETS". El detalle del error lo dice el
    propio /api/v1/impresion/estado en el campo "detalle", y quedan rastros en
    el Visor de eventos, registro PrintService/Operational.

  El pinpad no responde
    Revise que esté encendido y con su USB. Si el 401 no es el problema,
    pinpad.log dice en qué paso se quedó (apertura de PCL o espera del canal).

  El servicio no vuelve después de caerse
    El reintento automático es de un minuto y exige que la sesión del usuario
    esté abierta: la tarea arranca "At log on" de esa cuenta. Si la caja queda
    en la pantalla de inicio de sesión, el host no corre. Para que la caja
    arranque sola hasta el escritorio, configure el inicio de sesión automático
    de Windows. Alternativa equivalente: crear la tarea como "Al iniciar el
    sistema" con el usuario SYSTEM, o registrar el .cmd como servicio.

ARCHIVOS DEL PAQUETE
  SmartOne.Perifericos.Host.exe        El servicio (x64, .NET Framework 4.8)
  SmartOne.Perifericos.dll             El módulo de periféricos
  SmartOne.Perifericos.Host.exe.config Configuración: impresora_ticket
  PCLService.dll                       PCL de Ingenico (nativa x64)
  PCL_Bridge.dll                       Puente PCL (nativa x64)
  PclUtilities.dll                     Utilidades PCL (nativa x64)
  dllsign.dll                          Firma de la PCL (nativa x64)
  msvcp110.dll / msvcr110.dll          Runtime VC++ 2012 que exige la PCL
  IniciarPerifericos.cmd               Arranque a mano, con consola visible
  RegistrarArranqueAutomatico.ps1      Registra la tarea de arranque automático
  Instalar.ps1                         Instalador y verificador de esta caja
  PrepararImpresora.ps1                Crea la cola de la ticketera (pide UAC)
  LEEME.txt                            Este archivo
  version.txt                          Commit y fecha con que se armó el paquete
  token.txt                            Token pregrabado: la caja arranca sin tocar el .env

  CrearPaquete.ps1 no viene en el paquete: se ejecuta en la máquina de
  desarrollo para volver a armarlo.

  Al volver a armarlo sobre una carpeta que ya es una instalación --dist\ es la
  que usa la tarea programada de esta PC--, CrearPaquete.ps1 conserva
  bridge-url.txt, bridge-terminal.txt, bridge-token.txt, host.log y pinpad.log.
  Esos archivos no viajan en el ZIP: el ZIP lleva solo el manifiesto del
  paquete, sin secretos ni bitácoras. Para una caja nueva, copie aparte los tres
  bridge-*.txt o vuelva a ejecutar Instalar.ps1 en esa caja.

  Las versiones de las DLL nativas son fijas: son las que entrega Ingenico y no
  se reemplazan por otras.
